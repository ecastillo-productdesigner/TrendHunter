Article comments

Each Trend Detail article has its own discussion inside the article frame, after the member cue. A native Comments disclosure starts collapsed on desktop and mobile. Its count is always visible; Show comments / Hide comments opens and closes the composer and discussion. A 1px top divider separates it from the article. It inherits the article padding rather than adding another frame. Returning from sign-in to #comments deliberately expands the discussion. The heading pairs the supplied 20px Material Symbols chat icon with Section heading, comments use Body, timestamps and character counts use Helper, and posting uses the shared Primary button. Reader portraits are 32px. Reader names have no underline. Text actions have 48px minimum tap targets, separated by 8px, with visible keyboard focus and theme-aware colors.

Everyone can read. Only signed-in readers can post, reply, like or report. Each mutation checks authentication; edit and delete also check ownership. The inline Sign in or create an account link opens the existing login page and returns to #comments on the same article. Drafts survive that navigation and never post automatically. A comment is plain text, limited to 1,000 characters; empty input disables submission. One plain text sort button cycles Newest first (default), Oldest first and Most liked on click, Enter or Space, matching the Trending sort control. It has a 48px target with no dropdown, border or background. For signed-in readers, Commenting as and the sort button share one row, with 8px above and below it; the composer has a 16px lower gap. Sorting changes root threads while replies remain chronological. Three threads appear initially, with View all when needed. Thumb changes never move the current comment; sorting applies again when the reader switches the order. Replies are one level deep. Like uses the supplied heart at --spacing-layout-md (16 × 16px): outlined by default, filled when selected, with a visible count beside it. Unselected hearts and counts match the muted Reply and Report text; selected hearts and counts use the primary text color. It toggles off on a second click without moving the page. Own comments offer Edit and inline Delete confirmation; deleting a parent preserves replies. Other comments offer Report. Success uses the existing toast; a failed save keeps the draft.

Prototype scope: the three starting comments and their reader activity are fictional samples. Comments, likes and reports persist only in this browser, independently per article. The sign-in state is the existing browser-tab demo session. No comments or reports are sent to a server, other users, or a moderation team. A production release needs a shared service with server-side authentication, authorization and moderation.
